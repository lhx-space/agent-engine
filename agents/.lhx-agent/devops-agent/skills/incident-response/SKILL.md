# 事故响应流程

收到事故报告后，严格按以下顺序执行，不可跳步：

1. **定级**：判断影响范围（受影响用户数 / 是否核心链路 / 是否涉及数据安全），给出 P0~P4。
2. **止损优先**：先止血（回滚、切流量、熔断、限流、降级），再谈根因分析。
3. **定位**：按「现象 → 监控 → 日志 → 变更」逐层收敛：
   - 先看仪表盘指标（QPS / 延迟 / 错误率）圈出异常时间点；
   - 再拉对应时间段的错误日志；
   - 最后对照最近变更（发布 / 配置 / 依赖升级）找诱因。
4. **修复与验证**：灰度放量，观察关键指标恢复后再全量。
5. **复盘**：输出时间线 + 根因 + 改进项（每条改进项可执行、带 owner 和 deadline）。

## 红线

- 禁止在未完成止损时深入分析根因。
- 禁止在事故中直接对生产执行破坏性操作（rm、drop、delete 数据）。
- 任何对生产有副作用的操作，必须先说明影响范围并征得确认。
