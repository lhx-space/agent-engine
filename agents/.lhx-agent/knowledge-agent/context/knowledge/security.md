# 安全规范

> 本文档约束认证授权、密钥管理、注入防护、供应链安全与漏洞响应。任何涉及安全的需求/改动必须符合本文档。

## 一、认证与授权

### 1.1 认证

- 所有对外接口必须认证，头格式 `Authorization: Bearer <token>`。
- token 有有效期，过期强制刷新；泄露立即吊销。
- 敏感接口（管理/配置）加二次校验（OTP / 审批）。

### 1.2 授权

- 最小权限原则：服务账号只授予完成职责所需的最小权限。
- 禁止共用 root / 超级账号，各服务独立账号。
- 权限变更走审批，定期（每季度）做权限盘点回收。

## 二、密钥管理

### 2.1 存储与注入

- 密钥经环境变量 / 密钥管理系统（Vault / KMS）注入，**禁止硬编码进代码或提交仓库**。
- 配置里用 `${VAR}` 占位，运行时插值，真实值不入库。
- 生产密钥与开发密钥隔离，互不通用。

### 2.2 轮换与泄露

- 密钥定期轮换（建议 90 天）。
- 发现泄露：立即轮换 → 排查是否被滥用 → 复盘改进。
- 密钥在日志 / 报错 / 前端一律脱敏显示。

## 三、注入与越权防护

| 威胁        | 防护                                                                     |
| ----------- | ------------------------------------------------------------------------ |
| SQL 注入    | 参数化查询，禁止字符串拼接 SQL                                           |
| 命令注入    | bash 工具经 docker 沙箱（断网 + 只读 + 降权），命令白名单 + denyPatterns |
| 路径越权    | files 工具 `roots` 白名单 + realpath 越界校验                            |
| Prompt 注入 | 外部输入（网页/文档/MCP 返回）视为不可信，工具结果经 guardrails 校验     |
| XSS         | 前端渲染转义，禁止直接注入 HTML                                          |

## 四、数据安全

- 敏感数据（密钥、个人信息）落盘加密。
- 数据分级：公开 / 内部 / 机密 / 绝密，按级定访问与存储策略。
- 数据导出 / 删除走审批，留审计日志。
- 遵守合规要求（等保 / GDPR 等，按业务所在地区）。

## 五、供应链安全

- 依赖锁版本（lock 文件），升级前评审 changelog 与已知漏洞。
- 远程 MCP / skill 安装走「人在环」确认，**禁止 LLM 自动安装执行**。
- 第三方镜像 / 包用可信源，构建产物做签名校验。

## 六、漏洞响应

### 6.1 流程

````text
漏洞报告 → 评估影响面 → 定级 → 修复 → 验证 → 通告
```text

### 6.2 时限

| 级别 | 定义 | 修复时限 |
| --- | --- | --- |
| 严重 | RCE / 越权 / 数据泄露 | 24h 内 |
| 高危 | 认证绕过 / 注入 | 72h 内 |
| 中低危 | 信息泄露 / 配置问题 | 1 个迭代内 |
````
