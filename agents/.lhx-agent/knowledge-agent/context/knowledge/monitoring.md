# 监控告警规范

> 本文档定义指标体系、告警阈值、日志规范与可观测链路。所有服务的埋点、告警规则必须符合本文档。

## 目录

1. 指标体系
2. 告警阈值
3. 日志规范
4. 链路追踪
5. 告警处置流程

## 一、指标体系

采用 **RED + USE** 双视角：

- **RED**（服务视角）：请求量（Rate）、错误率（Errors）、延迟（Duration）。
- **USE**（资源视角）：利用率（Utilization）、饱和度（Saturation）、错误（Errors）。

### 关键指标清单

| 类别 | 指标                                     | 说明                    |
| ---- | ---------------------------------------- | ----------------------- |
| 请求 | `http_requests_total`                    | 按路由 / 状态码分桶     |
| 错误 | `http_errors_total`                      | 5xx 计数                |
| 延迟 | `http_duration_seconds`（P50/P95/P99）   | 分位数直方图            |
| LLM  | `llm_calls_total` / `llm_tokens_total`   | 模型调用数 / token 消耗 |
| 工具 | `tool_calls_total` / `tool_errors_total` | 工具调用数 / 失败数     |
| 资源 | CPU / 内存 / 磁盘 / 连接数               | 基础设施                |

## 二、告警阈值

| 指标          | 告警阈值            | 级别 | 说明        |
| ------------- | ------------------- | ---- | ----------- |
| 错误率（5xx） | > 1%（5 分钟窗口）  | P1   | 持续 5 分钟 |
| 可用性        | < 99.9%（SLO 违约） | P0   | 按月滚动    |
| P99 延迟      | > 500ms             | P1   | 核心接口    |
| CPU           | > 80% 持续 10 分钟  | P2   |             |
| 内存          | > 85% 或 OOM 风险   | P2   |             |
| 数据库连接数  | > 80% 上限          | P2   |             |
| 缓存命中率    | < 90%               | P3   |             |
| 磁盘使用率    | > 80%               | P2   |             |

### 告警规则要求

- 每条告警必须有明确的处置入口（Runbook 链接）。
- 避免告警风暴：同类告警聚合，加去重窗口。
- 定期 review 告警：误报率高（> 30%）的告警必须调整或下线。

## 三、日志规范

### 3.1 结构化日志

所有日志为 JSON，必带字段：

````json
{
  "ts": "2026-08-28T12:00:00Z",
  "level": "info",
  "service": "agent-engine",
  "trace_id": "abc123",
  "msg": "agent run completed",
  "agent": "devops-agent",
  "steps": 3
}
```text

### 3.2 分级

| 级别 | 用途 |
| --- | --- |
| error | 需告警的异常 |
| warn | 需关注的异常（如 MCP 连接失败已降级） |
| info | 关键路径（请求、run 完成、工具调用） |
| debug | 排查细节 |

### 3.3 脱敏

- 密钥、token、手机号、身份证号禁止写入日志。
- 统一走脱敏工具，`sk-***`、`138****1234`。

## 四、链路追踪

- 应用埋点（OTel）→ Prometheus 采集 → Grafana 看板。
- Trace 贯穿「入口 → LLM 调用 → 工具调用 → 结果」，关键耗时打点。
- 一次 agent run 的 trace 应能还原完整执行链（步数、工具、token、耗时）。

## 五、告警处置流程

```text
告警 → 值班确认（5min）→ 判误报？
                          ├─ 误报 → 调阈值 / 修规则
                          └─ 真实 → 按 Runbook 止损 → 定位 → 恢复 → 复盘
```text

恢复后 24h 内复盘，输出改进项（owner + deadline）。
````
